# 架构方案

本文为待实现方案，不代表功能已完成。

## 目标

用户继续在 Claude Code、Codex 等原客户端工作；通过 Skill 提示 Agent 使用真正的 MCP 工具记录任务、阶段、决策和成果。服务不接管或监控其他客户端会话。Windows、macOS、Linux 用户运行本地服务，在浏览器使用响应迅速、参考 Linear 的看板。业务状态为待做、进行中、已完成、待决策；另展示单任务甘特及全局时间线，计划与实际分开，缺失时间不虚构。

## 组件

- Node.js 本地 HTTP 服务、TypeScript、React/Vite 前端；同源 API 和 SSE 刷新。
- SQLite 持久化任务、结构化决策与事件，网页和 MCP 共用服务层；状态修改和事件须在同一事务中完成。Node 内置 `node:sqlite` 可避免本地原生扩展编译。
- 官方 MCP SDK 实现 stdio MCP；可用 stdio 进程桥接本地服务，仍由 SDK 实施 MCP 协议。服务未运行时明确报错。可进一步支持 Streamable HTTP，需验证协议与安全边界。
- 默认仅监听 loopback；本地接口须校验访问来源和请求，防范其他网页跨站发起写操作。数据目录和端口须可配置。

四态描述业务进度，不能代表 Agent 的运行情况。只有明确完成任务时设置完成时间；决策解决后显式选择恢复状态。甘特分别显示计划与实际时间，无日期则标记未排期或进行中，不推断结束。

每个状态变更事件记录前后状态，以真实时间重建任务状态时段；checkpoint 可记录阶段与下一步。决策包含选项、建议和选中的答案，供界面直接读取。默认数据库位于用户应用数据目录或 home 下的应用专属目录，允许通过 `DATA_DIR` 指定；不要默认存放于可能同步的仓库中。数据默认私密、不上传；测试数据库只放忽略的临时目录。开发任务种子仅由显式 seed 命令导入，默认空态，启动时不静默创建任务。

## 当前环境与目录

Windows 只读检查：Node 22.15.0、npm 10.9.2、Python 3.13.3。Node 22.15 支持 `node:sqlite`；SQLite 忙等待可使用 `PRAGMA busy_timeout`，不依赖 22.16 新增的构造参数。各平台需要实际验证。

拟议目录：`src/shared` 共享类型，`src/server` 服务与 MCP，`src/web` 浏览器界面，`tests` 验证，`docs` 文档。数据文件和构建产物不纳入版本控制。具体契约见 `api-contract.md`。
